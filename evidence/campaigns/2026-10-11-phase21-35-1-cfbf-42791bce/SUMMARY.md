# Phase 21.35.1 — CFBF / OLE2 compound-file court

**Question.** Does a CFBF/OLE2 compound file close exactly and expose a
representation-preserving physical-layer model (the header, the DIFAT/FAT, the
128-byte directory entries with verbatim UTF-16LE names incl. non-ASCII and a
reconstructed sibling/child tree, and each stream resolved to an exact byte
span — FAT-chained large streams and MiniFAT-chained small streams — with a
recorded cfb3/cfb4 dialect) on top of the whole-source exact leaf, while
staying honest at the detection boundary and declining malformed inputs typed?

**Method.** Each fixture is generated by the dependency-free
`examples/cfbf_fixtures.rs` writer, ingested via `field-build`, observed, then —
after the **source file and the standalone descriptor are deleted** —
rematerialized exactly in a fresh process and compared with `length + SHA-256 +
cmp`. The Opaque and structural controls pin the detection boundaries. The court
runs in the pinned `dev` service using only POSIX `sh`, coreutils, git, and the
shipped binary (no python3, no external OLE tooling, no network).

## Scope (honest)

- **Shipped here:** strong-magic + header-validation detection (the 8-byte
  signature at offset 0 **and** an internally consistent header — byte order
  `FFFE`, a major version of 3 or 4, a sector shift of 9 or 12 consistent with
  the version, a mini-sector shift of 6, at least one FAT sector, and a first
  directory sector inside the file); the parsed header, DIFAT (`109` header
  entries + chained DIFAT sectors), FAT and MiniFAT; the 128-byte directory
  entries with verbatim UTF-16LE names and the reconstructed red-black
  sibling/child tree; the exact stream spans (regular and mini); native
  `cfbf-dialect`/`cfbf-entry`/`cfbf-stream`/`cfbf-find`; common
  `metadata`/`text`/`search-match`; a recorded dialect.
- **Boundary:** a signature-only blob (its header fields are zero), a corrupted
  signature, a bad sector shift, an out-of-range directory sector, and prose all
  stay `Opaque`. A blob with a plausible header but a malformed body is admitted
  (its whole-source exact leaf is unaffected) and its model declines typed.
- **Declines:** an invalid directory object type, a cyclic/overlapping FAT or
  MiniFAT chain, an out-of-range sector ID, a truncated stream chain, and a
  header/sector-size mismatch are typed declines (`InvalidCfbfStructure`); a
  bad/short input stays `Opaque` rather than being claimed.
- **Exactness** is the whole source (a RAW-like `DocumentExact`): the
  compound-file model is derived and never on the exactness path (ADR-0060: the
  model node depends on the `sha256(source)` root).
- **Span caveat:** a stream's `data_span` is its exact `(offset, length)` when
  its sector chain is contiguous (the common case); a non-contiguous chain records
  a bounding hull and its `ExactBytes` declines typed rather than returning
  interleaved foreign bytes.
- **Not claimed here:** the legacy DOC/XLS/PPT/MSG *semantic* models (later
  subphases); the economic court (separate script).
- **Never run on the host:** every command above ran in the pinned `dev`
  container.
