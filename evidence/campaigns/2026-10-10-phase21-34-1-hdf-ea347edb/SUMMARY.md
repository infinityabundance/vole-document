# Phase 21.34.1 — scientific-container (NetCDF classic / HDF5-subset) court

**Question.** Does a NetCDF classic (CDF-1/CDF-2) or HDF5-subset file close
exactly and expose a bounded, span-preserving model (NetCDF: the dimension table
incl. the unlimited dimension, the global attributes, and the variable list; HDF5:
the group/dataset tree with the dataset datatype / simple dataspace / contiguous
layout and the root-group attribute; a recorded `netcdf`/`hdf5` dialect) on top of
the whole-source exact leaf — while declining out-of-subset HDF5 constructs,
malformed headers, and non-magic inputs typed?

**Method.** Each fixture is generated by the dependency-free
`examples/hdf_fixtures.rs` writer, ingested via `field-build`, observed, then —
after the **source file and the standalone descriptor are deleted** —
rematerialized exactly in a fresh process and compared with `length + SHA-256 +
cmp`. The out-of-subset, structural, and Opaque controls pin the boundaries. The
court runs in the pinned `dev` service using only POSIX `sh`, coreutils, git, and
the shipped binary (no python3, no h5py, no h5dump, no netCDF).

## Scope (honest)

- **Shipped here:** content-only, conservative detection (NetCDF = the
  `CDF\x01`/`CDF\x02` magic; HDF5 = the signature at 0 or 512 with a validated
  superblock header); the bounded, span-preserving NetCDF-classic model; the
  documented HDF5 subset; native `hdf-dialect`/`hdf-object`/`hdf-dimension`/
  `hdf-attribute`/`hdf-find`; common `metadata`/`text`/`search-match`; a recorded
  dialect.
- **Declines:** superblock v2/v3, v2/v3 object headers, compact/chunked/virtual
  layouts, filtered datasets, external data files, and every datatype class other
  than fixed-point/float/string (rc 6); malformed headers (rc 50); a bad/truncated
  input stays `Opaque` rather than being claimed.
- **Exactness** is the whole source (a RAW-like `DocumentExact`): the model is
  derived and never on the exactness path (ADR-0060: the model node depends on the
  `sha256(source)` root).
- **Not claimed here:** dataset value decoding, filtered-data decompression, the
  HDF5 v2 link machinery, and the economic court (separate script).
- **Never run on the host:** every command above ran in the pinned `dev` container.
