## What is genuinely shared (exact content identity)

* the byte-identical resource resolves to **one** `ResourceBlob` content id in
both the DOCX and the EPUB (verified `contains_node`), and the decoded member
shares that same blob id;
* the second document writes 0 bytes for the shared blob (a representation fact,
`nodes_id_shared`), reported separately from work reuse (`nodes_reused`);
* work reuse is measured as a fraction of receipted inverse-work units (node
executions + cold input bytes), never from source size.

## What is not shared

* the Phase-11 **PDF** adapter extracts no embedded resource blob, so PDF↔DOCX
resource sharing does not exist (recorded, not a failure);
* raw compressed (DEFLATE) members and per-source span records are not content
identity and are not claimed as sharing;
* the no-sharing control (different bytes) shares no resource, shares no node
id, and deduplicates zero bytes.

## Accounting scope (no compression claim)

`seed_bytes_saved_on_second_document` is the *seed-node record* bytes the second
document did not rewrite because the blob and decoded member were already present.
It is NOT an overall store-size saving: each document's exact source descriptor
is stored independently and still contains the resource bytes. A shared blob is
therefore scored as state/work, never as an achieved store-size fraction.
