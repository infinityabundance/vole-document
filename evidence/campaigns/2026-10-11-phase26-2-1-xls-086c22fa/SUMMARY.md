# Phase 26.2.1 — legacy Excel 97–2003 (`.xls`, BIFF8) court

**Question.** Does a legacy Excel 97–2003 workbook close exactly and expose a
representation-preserving semantic model (the BIFF8 record stream, the ordered
`BOUNDSHEET` sheets, the `SST` shared-string table with `CONTINUE` reassembly, and
each cell's row/column, exact record span, and exact stored value spelling, with
the `RK` compact numeric encoding decoded) **on top of the reused CFBF/OLE2
physical layer**, while staying honest at the detection boundary and declining
malformed inputs typed?

**Method.** Each fixture is generated by the dependency-free
`examples/xls_fixtures.rs` writer, ingested via `field-build`, observed, then —
after the **source file and the standalone descriptor are deleted** —
rematerialized exactly in a fresh process and compared with `length + SHA-256 +
cmp`. The CFBF, Opaque, and structural controls pin the detection boundaries. The
court runs in the pinned `dev` service using only POSIX `sh`, coreutils, git, and
the shipped binary (no python3, no Excel tooling, no network).

## Scope (honest)

- **Supported:** detection on top of the CFBF layer (the `Workbook`/`Book` stream
  begins with a BIFF8 `BOF` — id `0x0809`, version `0x0600` — whose substream type
  is a recognized worksheet/globals type); the record stream
  (`[u16 id][u16 len][payload]`) with every record's exact byte span; the
  `BOF`/`EOF` substream framing and the BIFF version; the `BOUNDSHEET` sheets (name
  and `BOF` stream position, in order); the `SST` shared-string table (with
  `CONTINUE` reassembly); the per-sheet cells
  (`LABELSST`/`NUMBER`/`RK`/`BOOLERR`/`FORMULA`+`STRING`/`BLANK`/`MULBLANK`) with
  their row/column, exact record span, and exact stored value spelling (the `RK`
  compact numeric encoding is decoded); `DIMENSIONS`/`ROW`/`FORMAT`/`XF` recorded by
  span; native `xls-biff`/`xls-sheet`/`xls-cell`/`xls-record`/`xls-find`; common
  `metadata`/`text`/`search-match`.
- **Boundary:** a generic compound file, a `.xls` with a bad `BOF` version
  (BIFF5/7), and a `.xls` with an unrecognized substream type stay `Cfbf`; prose
  stays `Opaque`; a `.xlsx` (an OPC ZIP) never reaches the CFBF detector at all; a
  `.xls` with a plausible BIFF8 `BOF` but a malformed body is admitted and its
  model declines typed.
- **Declines:** a bad `BOF` version, an unrecognized substream type, a leading
  substream that is not workbook globals, a truncated record, an out-of-range
  `BOUNDSHEET` position, an `SST` count mismatch or a malformed `CONTINUE`, and a
  `FORMULA` string result with no `STRING` record are typed declines
  (`InvalidXlsStructure`).
- **Not claimed here:** BIFF5/7 (an older `Book` stream with 1-byte string
  lengths), password-encrypted/obfuscated workbooks, and the other legacy CFBF
  semantic models (PPT/MSG, later subphases); the economic court (separate script).
- **Exactness** is the whole source (a RAW-like `DocumentExact`): the XLS model
  is derived and never on the exactness path (ADR-0060: the model node depends on
  the `sha256(source)` root).
- **Never run on the host:** every command above ran in the pinned `dev`
  container.
