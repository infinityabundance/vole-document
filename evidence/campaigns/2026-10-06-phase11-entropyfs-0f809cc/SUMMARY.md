## The one hard exactness rule

```
materialized_length == source_length
SHA256(materialized) == SHA256(source)
byte_compare(materialized, source) == equal
```

All three hold after a process exit, a fresh process, a cache clear, and with the
working source removed. Exactness is produced by the standalone `.voldoc`
materializer; the EntropyFS substrate holds no decoder authority (ADR-0008,
ADR-0025).

## Honesty / limitations

- **EntropyFS is a blob store here.** Every seed node is an opaque, domain-prefixed
  engine blob; the engine has no notion of a node, node kind, dependency edge, or
  materializer. VOLE owns the canonical node format entirely. The claim is
  **persistence granularity** — one node per blob, each independently fetchable and
  range-readable — **not** that EntropyFS understands procedural nodes.
- **No speed claim.** No wall-clock or throughput comparison is made.
- The identity trick: a `NodeId` is `BLAKE3("VOLE:PSEED:v1" || canonical)`, so the
  adapter stores the domain-prefixed bytes and the engine's `BlobId` equals the
  `NodeId` exactly; `get_blob`'s whole-blob BLAKE3 gate *is* the node-identity gate.
  Descriptors are stored raw (`Id = BLAKE3(bytes)`); manifests are stored
  domain-prefixed with `VOLE:VFIELD:v1` (`FieldId`). A seed node, a descriptor, and
  a manifest can never collide (distinct domains / distinct bytes).
- **No enumeration through the engine.** `SeedStore::list_nodes` and
  `FieldStore::list_fields` **decline** with `UnsupportedFeature`; the engine has no
  list/iter. Dependency closure by explicit id still works, but a seed-store
  mark-and-sweep GC cannot be computed through this substrate, and that is reported
  rather than faked.
- **Durability barrier required.** The engine acks a `put_blob` at rename but does
  not barrier, so a fresh open in another process can miss the pending epoch. The
  court therefore calls `FieldStore::sync()` (engine barrier) after every mutating
  command; without it the page-deepen writes were observed to be lost across a
  process boundary during development. This is recorded as a real constraint, not
  hidden.
- **Partial descriptor reads are unavailable** on this backend (the descriptor is
  an engine blob, not a seekable file), so observations use the full descriptor
  path (`descriptor_read_mode=full`).
- The **index** remains `FsIndexStore` (files under `<root>/index`); this subphase
  moved only descriptor + manifest + seed nodes into the engine.

## Engine blob accounting is EntropyFS's own

`blob_count` / `logical_bytes` / `physical_used_bytes` come from
`Engine::metrics()` via `field-store-stats`; they are advisory engine numbers with
no exactness meaning.
